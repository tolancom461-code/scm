# Procure Nexus — المشاريع والمستخلصات

الواجهة الافتراضية منذ 11 أكتوبر 2026 تربط المشروع بالعقد والمستخلص المعتمد وجدول الدفعات. يرى المحاسب المصروف والمستحق المتبقي والضمان والدفعة القادمة، ثم يسجل المبلغ والتاريخ ورقم السند بعد الصرف من برنامجه المحاسبي. راجع [دليل المرحلة الأولى](docs/PHASE_ONE_GUIDE.md) و[حالة المشروع](docs/PROJECT_STATUS.md).

الدورة السابقة للمشتريات والاستلام والمخزون والفواتير محفوظة ويمكن فتحها من «الدورة السابقة». دليلها التاريخي في [MVP_GUIDE.md](docs/MVP_GUIDE.md). أرصدة المرحلة الأولى تخص عملياتها؛ لم تُرحّل إليها دفعات الدورة السابقة تلقائيًا.

محرك الترقيم المركزي يولّد للمشاريع والعقود والمستخلصات أرقامًا مثل `PRJ-26-10-0001` و`CTR-26-10-0001` و`IPC-26-10-0001`. الشهر والسنة بتوقيت السعودية، والتسلسل مستقل لكل نوع وسنة ويستمر عبر الأشهر. تبقى الأرقام السابقة ثابتة، وتظهر المراجع المرتبطة في الواجهة والطباعة. الترحيل 0011 يضيف أرقام مشاريع المرحلة الأولى؛ أوقف عمليات الكتابة أثناء تطبيقه وشغّل الخادم المحدث بعده.

## التشغيل

يتطلب Node.js وحزم المشروع وقاعدة MySQL/TiDB عبر TLS. يقرأ الخادم `DATABASE_URL` من `.env`. لا تضع بيانات الاتصال أو كلمات المرور في المستودع.

منفذ التشغيل الافتراضي `3050`، والإعداد الحالي في `.env` هو `PORT=3050`. افتح `http://localhost:3050` بعد التشغيل.

```powershell
npm run db:migrate
npm run dev
```

قاعدة المشروع الحالية رُحّلت بالفعل. `db:baseline` مخصص لتسجيل تاريخ قاعدة تجريبية قديمة بعد مطابقة مخططها، وليس للتشغيل الدوري. القاعدة الجديدة الفارغة تستخدم `db:migrate`. ينشئ سكربت الترحيل نسخة من تعريفات الجداول قبل التغيير؛ هذه ليست نسخة احتياطية من محتويات البيانات.

عند عدم وجود حسابات، أنشئ المسؤول عبر شاشة التأسيس. أمر `npm run admin:create` بديل يتطلب `ADMIN_USERNAME` و`ADMIN_PASSWORD` بطول 12 حرفًا على الأقل، ويمكن ضبط `ADMIN_NAME`. لا توجد كلمة مرور افتراضية ثابتة.

`npm run db:seed` يزرع بيانات مرجعية تجريبية دون تكرار رموزها. يتطلب مسؤولًا موجودًا أو متغيرَي المسؤول السابقين. `npm run db:demo` ينشئ مشروع تدريب:20 شجرة بقيمة 200,000 ريال مع استلام وفاتورة ودفعات 60,000 و 80,000 و 60,000، وعقد أعمال 100,000 ريال منجز منه 50,000 مع طلب دفع ينتظر الاعتماد. حسابات التدريب وكلمة مرورها العشوائية محفوظة محليًا في `.mvp-demo-credentials.json`؛ لا تُنشر. إعادة الأمر لا تكرر المشروع الموجود.

## الاستخدام الحالي

ابدأ بالبيانات المرجعية ومسارات الموافقات والمستخدمين، ثم أنشئ مشروعًا ومراحل وميزانية معتمدة. من «دورة الشراء» أنشئ أمر مواد أو عقد أعمال مباشرة. سجل الاستلام والفحص للمواد، أو محضر إنجاز للأعمال، ثم أنشئ الفاتورة وطابقها واعتمدها. أنشئ جدول الدفعات وطلبات الدفع وافصل المستخدم المنشئ عن المعتمد. «المركز التشغيلي» يعرض الميزانية والكميات والمدفوع والتأخر. التفاصيل في [دليل النسخة المبسطة](docs/MVP_GUIDE.md).

الدورة القديمة محفوظة في المشروع، وتعرض الواجهة المبسطة الدورة الجديدة. RFQ والعروض والترسية اختيارية عبر زر الدورة المتقدمة. فصل الواجبات والتحقق من الميزانية والكميات والأسعار والأرصدة يجريان على الخادم. الدفع تسجيل داخلي وليس تحويلًا بنكيًا. نطاق SCM الكامل والتكامل المحاسبي واللوجستي المتقدم مؤجلان.

المرفقات تستخدم التخزين الخارجي عند ضبطه، وإلا تُحفظ في `.data/documents` أو `FILE_STORAGE_DIR`. التنزيل محمي بالمصادقة وصلاحيات الوثائق. انسخ محتويات القاعدة ومسار الملفات معًا عند إعداد النسخ الاحتياطي.

## الفحوص

```powershell
npm run check
npm run test:unit
npm run test:numbering:integration
npm run test:numbering:migration
npm run build
npm run test:phase-one:integration
npm run test:phase-one-ui
npm run test:users:integration
npm run test:users-ui
npm run test:mvp:integration
npm run test:mvp-ui
```

اختبارات المرحلة الأولى تحتاج القاعدة المهيأة وتنشئ حسابات وبيانات اختبار معزولة وتنظفها عند النهاية. اختبار الواجهة يستخدم Edge وPlaywright وخادمًا مؤقتًا، أو رابط خادم قائم عبر `PHASE_ONE_UI_URL`. اختبارات الدورة السابقة `test:mvp:*` تحتاج مشروع التدريب القديم. السكربت القديم `test:runtime` يفترض Linux ولم يُتحقق منه على Windows ضمن هذه المرحلة. الأدلة الحالية في [سجل الاختبارات](docs/TESTING.md).
