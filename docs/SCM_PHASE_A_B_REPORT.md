## Summary

احتُفظ بالتقنيات الحالية. فُصلت مسارات الخادم وصفحات الواجهة إلى وحدات، وأضيفت بيانات مرجعية بالنطاق أدناه. أُصلحت مسودات ملاحق العقود والترقيم وتأسيس المسؤول واستبدال الصلاحيات وتنزيل الوثائق. رُحلت قاعدة TiDB الحالية وزُرعت بيانات مرجعية دون حذف البيانات القديمة.

## Database

أضيفت 13 جدولًا: `document_sequences`, `operation_keys`, `scm_audit_events`, `scm_outbox`, `scm_categories`, `scm_units`, `scm_branches`, `scm_sites`, `scm_cost_centers`, `scm_warehouses`, `scm_warehouse_locations`, `scm_items`, `scm_uom_conversions`.

مفاتيح أجنبية وفهارس ورموز فريدة ونسخة تعديل للبيانات المرجعية، وقيود للتحويلات والتتبع. تاريخ الترحيل القديم كان ناقصًا؛ طوبقت أعمدة وفهارس مخطط 0004 قبل تسجيله وتطبيق 0005. لم تُصفّر البيانات القديمة. نظفت الاختبارات سجلاتها المعزولة.

`docs/baseline-scm/` يحفظ المخطط والترحيلات الأصلية وتعريفات SHOW CREATE TABLE قبل الترحيل. هذا احتياط للمخطط فقط، وليس للصفوف. MySQL DDL غير قابل للتراجع كوحدة واحدة؛ الفشل الجزئي يتطلب فحصًا وإصلاحًا قبل إعادة التشغيل.

## APIs / UI

`masterData.list`, `detail`, `create`, `update` للأنواع التسعة: بحث وترشيح وفرز وصفحات في SQL، تفاصيل وإنشاء وتعديل وتعطيل، وأسماء إلزامية بثلاث لغات. المراجع قابلة للبحث وتظهر أسماؤها في التفاصيل. حماية العرض والإدارة على الخادم.

إجراءات ملحق العقد: إرسال ومراجعة وسريان، مع أزرار الواجهة وصلاحيات العقود القائمة. بقيت APIs القديمة للتحول التدريجي؛ ليست دورة SCM مكتملة.

## Rules / Permissions

- `master.view` للعرض و`master.manage` للتغيير. الإدارة لا تتجاوز فصل الواجبات في الملحق.
- مفتاح إعادة المحاولة يعيد نفس ID لنفس المستخدم والعملية والمحتوى، ويرفض محتوى مختلفًا بنفس المفتاح.
- مرجع نشط، منع دورات التصنيف، قفل التحديث وفحص النسخة. بعض الخصائص الجوهرية ثابتة لحماية التاريخ المستقبلي.
- التغيير والتدقيق وoutbox بمعاملة واحدة للبيانات المرجعية وانتقال الملحق؛ لم يعمم ذلك على جميع المسارات القديمة.
- الحساب الجديد fixed-point وDECIMAL نصي؛ حسابات قديمة ما زالت Number إلى حين استبدالها.
- الترقيم مقفول؛ المسارات القديمة تحجز الرقم بمعاملة منفصلة وقد تترك فجوات عند فشل الإنشاء.
- المسودة لا تغيّر العقد؛ منشئها يرسلها وشخص آخر يراجعها ويطبقها. السريان يحدّث القيمة والمدة والحالة والتدقيق معًا.

## Tests / TypeScript / Build

- TypeScript كامل `tsc --noEmit --incremental false`: ناجح.
- Vitest: 47 اختبار وحدات ناجح؛ تكامل القاعدة اختياري خارج التشغيل العادي.
- TiDB: 9 اختبارات تكامل ناجحة تشمل idempotency والتزامن وrollback وFK والنسخة والتصنيف والترقيم والبحث. ملحق العقد اختُبر من المسودة إلى طلبَي سريان متزامنين وطُبق مرة واحدة.
- Windows/Edge: دخول وإنشاء فرع وبحث وتفاصيل وتعديل وتبديل AR/EN/UR وRTL/LTR، كمبيوتر وهاتف، دون أخطاء JavaScript. الصور `scm-master-desktop.png` و`scm-master-mobile.png`.
- بناء Vite وExpress عبر esbuild: ناجح. تحذير لحزمة واجهة كبيرة واستيراد xlsx مختلط؛ لم يعالج الأداء ضمن الحزمة.
- دورة الزيتون وافتتاح الفرع الكاملة لم تُبن، ولم يثبتها الاختبار. سكربت runtime القديم الخاص بـLinux لم يشغّل على Windows.

## Security / Known Issues / Debt

إزالة كلمة مرور المسؤول الثابتة؛ تأسيس المسؤول واستبدال الصلاحيات بمعاملات وقفل؛ تنزيل الوثائق يتحقق من الجلسة والصلاحية والسرية؛ رسائل الأخطاء الجديدة آمنة ومترجمة. هذا ليس تدقيقًا أمنيًا شاملًا أو شهادة جاهزية إنتاج.

متبقٍ: محرك الموافقات والتفويض والحدود؛ عامل outbox؛ تعميم التدقيق والمعاملات وidempotency؛ rate limiting مستمر؛ بنود المستندات المترابطة؛ تنظيم تخزين الملفات؛ تقسيم حزمة الواجهة؛ اختبار بقية الصفحات في المتصفح؛ اختبار استعادة محتويات القاعدة. db.ts ما زال يحمل منطقًا قديمًا.
