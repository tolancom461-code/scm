# مركز السياسات والصلاحيات

## الاستخدام

من «المستخدمون والصلاحيات» اختر «إضافة مستخدم» أو «تعديل البيانات». حقل «الدور» قائمة منسدلة تحمل قوالب الأدوار. اختيار دور يحمّل صلاحياته الافتراضية، ويمكن إضافة أو سحب صلاحيات ذرية لهذا المستخدم في النموذج نفسه، مع تحديد المشاريع. تُحفظ بيانات الحساب والدور والصلاحيات معًا في معاملة واحدة؛ أي فشل أو تعارض يمنع الحفظ الجزئي. ويمكن استخدام «مركز الصلاحيات» مباشرة لإدارة سياسة حساب موجود.

القالب نقطة بداية ثابتة: تعديل صلاحيات المستخدم لا يغيّر القالب أو بقية المستخدمين، ولا يعيد الخادم فرض صلاحيات القالب المسحوبة عند الحفظ. يبقى اسم الدور المختار محفوظًا حتى مع التخصيص. تغيير الدور في القائمة يعيد تحميل صلاحيات القالب الجديد ويلغي التخصيص السابق في النموذج؛ إعادة فتح المستخدم تعرض صلاحياته المحفوظة كما هي. إضافة إجراء تضيف متطلباته تلقائيًا، وسحب صلاحية عرض يسحب الإجراءات المعتمدة عليها أيضًا. مثلًا يمكن اختيار «المحاسب» ثم سحب «تسجيل الصرف الفعلي» مع إبقاء عرض المصروف والأرصدة.

اختيار أو تعديل السياسة يتطلب `policy.manage` إضافة إلى صلاحية إنشاء أو تعديل بيانات المستخدم. من يملك إدارة البيانات فقط يرى الدور دون إمكانية تغييره، ويمكنه إنشاء حساب مغلق الصلاحيات لتجهيزه لاحقًا بواسطة مسؤول الصلاحيات. قوالب الأدوار نفسها معرفة مركزيًا في الشيفرة، ولا يوجد محرر للقوالب العامة من الواجهة حاليًا.

اختر دورًا ثم المشاريع المسموح بها. يمكن اختيار «جميع المشاريع الحالية والمستقبلية»، أو مشاريع محددة. اختيار دور وحده لا يمنح وصولًا إلى مشاريع غير محددة. إذا مُنح المستخدم إنشاء مشروع، يضاف المشروع الذي ينشئه إلى نطاقه تلقائيًا.

| الدور                  | الوظائف الافتراضية                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| مدير النظام            | كامل الصلاحيات المعروفة وجميع المشاريع؛ تظل قاعدة منع اعتماد مستخلص أنشأه بنفسه سارية                          |
| مسؤول المشاريع والعقود | إنشاء المشاريع والعقود والمستخلصات، إدارة بيانات الموردين ورفع المرفقات؛ لا يعرض الصرف الفعلي والأرصدة         |
| معتمد المستخلصات       | عرض العقود والمستخلصات، اعتماد أو رفض مستخلص أعده مستخدم آخر؛ لا يسجل صرفًا                                    |
| المحاسب                | عرض المستخلصات والأرصدة والدفعة القادمة، تسجيل الصرف الفعلي والسند والتاريخ ورفع مرفق الصرف؛ لا يعتمد مستخلصًا |
| مراقب / إدارة عليا     | عرض العقود والمستخلصات والمصروف والأرصدة دون إنشاء أو اعتماد أو صرف                                            |
| صلاحيات مخصصة          | اختيار الإجراءات المتاحة لهذا الحساب؛ متطلبات العرض اللازمة للإجراء تضاف تلقائيًا                              |

الإفراج عن الضمان صلاحية مستقلة، ولا يمنح تلقائيًا للمحاسب أو المعتمد. يمكن إضافتها لمن يعتمد انتهاء الضمان حسب تنظيم الشركة. تعديل بيانات الشركة، وإدارة المستخدمين وكلمات المرور، وإدارة المركز صلاحيات مستقلة أيضًا.

حساب مدير النظام الحالي يعرض باعتباره كامل الصلاحيات، ولا يحوّل إلى دور محدود من هذه الشاشة. تعطيله يتم من صفحة المستخدمين مع حماية الحساب الحالي. لم يغير الترحيل أدوار الحسابات الموجودة أو كلمات مرورها؛ يجب مراجعة الحسابات التي تحمل دور المدير إذا كان المطلوب توزيع العمل بين موظفين محدودي الصلاحيات.

صلاحيات المستخدم ونطاق مشاريعه تتغير على الخادم في الطلب التالي. الواجهة تحدث الهوية عند العودة للنافذة وكل 30 ثانية؛ لا حاجة لتسجيل خروج ليطبق المنع في الخادم. لا يمكن سحب مستند سبق للمستخدم تنزيله قبل إلغاء صلاحيته.

## حدود البيانات

- نطاق المشروع يطبق على مشاريع وعقود ومستخلصات ودفعات المرحلة الأولى، وعلى قوائم المرفقات وتنزيلها ورفعها.
- قيم العقود والمستخلصات وجدول الدفعات التعاقدي متاحة لمن يملك صلاحيات عرضها. عرض المصروف الفعلي والأرصدة والإفراج عن الضمان يتطلب `p1.payments.view`. لا يرسل الخادم هذه البيانات للحساب الذي لا يملكها.
- دليل الموردين بيانات مشتركة على مستوى المؤسسة، وله صلاحيات عرض وإنشاء وتعديل مستقلة. وجود مورد مشترك لا يكشف عقوده في مشروع خارج النطاق.
- المرفقات السرية تحتاج `documents.view_confidential` بالإضافة إلى صلاحية عرض السجل الأصلي ونطاق مشروعه. مرفق سند الصرف يحتاج صلاحية عرض الصرف.
- الدورة السابقة لم تحول إلى نظام نطاق مشاريع جديد. الدخول إليها يتطلب سماحًا صريحًا ونطاق جميع المشاريع؛ الحساب المقيد بمشاريع معينة لا يستطيع استخدامها لتجاوز نطاق المرحلة الأولى. صلاحياتها التفصيلية تظل لازمة.

يعرض المركز آخر 100 محاولة وصول مرفوضة: الحساب والإجراء وسبب المنع والوقت. تحفظ تغييرات السياسات أيضًا في سجل التدقيق، دون تسجيل كلمات المرور أو محتويات الملفات في سجل المنع.

من يدير سياسات المستخدمين لا يستطيع منح صلاحية أو نطاق مشاريع أوسع مما يملكه، ولا يستطيع تعديل أو إعادة تعيين كلمة مرور حساب أوسع صلاحية منه. الحفظ المتزامن لنفس السياسة يستخدم رقم إصدار؛ يظهر تعارض عند محاولة حفظ نسخة قديمة بدل الكتابة فوق آخر تعديل.

## إضافة وظيفة مستقبلية

المركز قابل للتوسعة، لكن الوظيفة الجديدة لا تصبح مسموحة تلقائيًا:

1. أضف الصلاحية إلى `shared/permissions.ts` وحدد الوصف بلغات الواجهة.
2. سجل المسار في `server/core/policy-registry.ts` وحدد الصلاحيات اللازمة. افحص نطاق السجل في `server/core/policy.ts` وأضف فلاتر الاستعلام وحقول الاستجابة المناسبة.
3. أضفها إلى قوالب الأدوار عند الحاجة، وحدد متطلبات العرض في `shared/policy.ts`. لا تضفها إلى جميع المستخدمين تلقائيًا.
4. حدث واجهتها ومركز الصلاحيات إذا أضيف نوع نطاق أو شرط جديد، وأضف اختبار طلب مباشر مسموح وآخر مرفوض، واختبار نطاق وحقول ومرفقات إن وجدت.
5. شغل فحص الأنواع واختبارات السياسات. اختبار التغطية يقارن جميع مسارات API بالسجل المركزي؛ المسار غير المسجل يمنع حتى للمدير.

استخدم أدوات الإجراءات المشتركة في `server/_core/trpc.ts`. قرار السماح يعاد حسابه من المستخدم النشط والصلاحيات والنطاق في القاعدة لكل طلب، ولا يؤخذ من الدور أو البيانات المرسلة من المتصفح. عند تعذر قراءة السياسة لا تنفذ العملية.

## قاعدة البيانات والتحقق

الترحيل `0012_rapid_cobalt_man.sql` يضيف `access_profiles` و`access_projects` و`access_denials`، ويسجل صلاحيات المرحلة الأولى المستقلة. يحفظ صلاحيات الحسابات القائمة ونطاقها السابق، ويضيف مقابلات المرحلة الأولى للصلاحيات السابقة. الحسابات الجديدة تبدأ بنطاق مغلق. الترحيل طبق على القاعدة الحالية؛ لا تعدل ملف ترحيل سبق تطبيقه.

```powershell
npm run check
npm run test:unit
npm run test:policy:integration
npm run test:policy-ui
```

اختبارات التكامل والواجهة تنشئ حسابات ومشاريع وملفات مؤقتة ببادئة `P1TEST-` وتنظفها بعد النهاية، وتترك العدادات متقدمة حتى لا يعاد استخدام رقم صدر سابقًا. لا تحتاج إلى كلمة مرور المالك الفعلي.
